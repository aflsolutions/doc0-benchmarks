## Overview

GraalVM native image compilation for Resilience4j bridges the gap between dynamic framework features and static runtime analysis by registering essential reflection hooks, proxies, and AOT hints across Spring and Micronaut modules. Because native compilation strips unused classes and methods, runtime aspects, fallback executors, and expression resolvers require explicit metadata registration to function properly.

Sources: [resilience4j-spring-boot3/src/main/java/io/github/resilience4j/springboot3/nativeimage/configuration/NativeHintsConfiguration.java#L1-L39](https://github.com/resilience4j/resilience4j/blob/main/resilience4j-spring-boot3/src/main/java/io/github/resilience4j/springboot3/nativeimage/configuration/NativeHintsConfiguration.java#L1-L39), [resilience4j-spring-boot4/src/main/java/io/github/resilience4j/springboot/nativeimage/configuration/NativeHintsConfiguration.java#L1-L36](https://github.com/resilience4j/resilience4j/blob/main/resilience4j-spring-boot4/src/main/java/io/github/resilience4j/springboot/nativeimage/configuration/NativeHintsConfiguration.java#L1-L36)

## Native Hints Configuration Infrastructure

### Native Hints Configuration Infrastructure

Spring Boot 3 and Spring Boot 4 integration modules configure GraalVM Native Image compilation by implementing Spring's `RuntimeHintsRegistrar` interface. The `NativeHintsConfiguration` class in both `resilience4j-spring-boot3` and `resilience4j-spring-boot4` explicitly registers target types and member categories via `RuntimeHints`, ensuring that AOP aspects, fallback execution mechanisms, and expression evaluation contexts remain accessible at runtime under closed-world assumptions.

Sources: [resilience4j-spring-boot3/src/main/java/io/github/resilience4j/springboot3/nativeimage/configuration/NativeHintsConfiguration.java#L9-L11](https://github.com/resilience4j/resilience4j/blob/main/resilience4j-spring-boot3/src/main/java/io/github/resilience4j/springboot3/nativeimage/configuration/NativeHintsConfiguration.java#L9-L11), [resilience4j-spring-boot4/src/main/java/io/github/resilience4j/springboot/nativeimage/configuration/NativeHintsConfiguration.java#L7-L10](https://github.com/resilience4j/resilience4j/blob/main/resilience4j-spring-boot4/src/main/java/io/github/resilience4j/springboot/nativeimage/configuration/NativeHintsConfiguration.java#L7-L10)

### Registration Mechanics and Member Categories

The hint registration process is driven by the `registerHints(RuntimeHints hints, ClassLoader classLoader)` method. Within this method, reflection hints are applied to resilience aspects, fallback components, and utility classes by invoking `hints.reflection().registerType()` coupled with specific `MemberCategory` enums.

## Circuit Breaker Reflection and Aspect Setup

### Overview

The aspect-oriented programming (AOP) infrastructure for circuit breakers is coordinated through `CircuitBreakerConfiguration` in Spring 6 and extended by `CircuitBreakerAutoConfiguration` in Spring Boot 4 and `AbstractCircuitBreakerConfigurationOnMissingBean` in Spring Boot 3. These configurations instantiate runtime aspects, event registries, and dynamic proxies under specific classpath and container conditions.

### Interception and Execution Call Chain

When a method annotated with `@CircuitBreaker` is invoked, execution flows through the AOP advice and downstream handlers. The call sequence proceeds as follows:

`circuitBreakerAroundAdvice()` extracts the target method signature and resolving backend names via `SpelResolver` → `getOrCreateCircuitBreaker()` looks up configuration keys and retrieves or creates the circuit breaker instance → `proceed()` inspects return types or extensions via `circuitBreakerAspectExtList` → if no extension matches and the return type is a `CompletionStage`, `handleJoinPointCompletableFuture()` executes; otherwise, `defaultHandling()` delegates to `circuitBreaker.executeCheckedSupplier()` → `fallbackExecutor.execute()` wraps the invocation to manage fallback methods if an exception occurs.

### Micronaut Circuit Breaker Registry Integration

In Micronaut environments, circuit breaker infrastructure is initialized via factory classes annotated with `@Factory` and conditionalized using property checks. The `CircuitBreakerRegistryFactory` inspects `resilience4j.circuitbreaker.enabled`, requiring a boolean value of true before loading registry components into the application context.
Sources: [resilience4j-micronaut/src/main/java/io/github/resilience4j/micronaut/circuitbreaker/CircuitBreakerRegistryFactory.java#L45-L47](https://github.com/resilience4j/resilience4j/blob/main/resilience4j-micronaut/src/main/java/io/github/resilience4j/micronaut/circuitbreaker/CircuitBreakerRegistryFactory.java#L45-L47)

The factory coordinates customizers, event consumer registries, and registry event consumers to construct the final `CircuitBreakerRegistry`:

```java
@Factory
@Requires(property = "resilience4j.circuitbreaker.enabled", value = StringUtils.TRUE, defaultValue = StringUtils.FALSE)
public class CircuitBreakerRegistryFactory {
    @Bean
    @CircuitBreakerQualifier
    public CompositeCustomizer<CircuitBreakerConfigCustomizer> compositeCircuitBreakerCustomizer(
        @Nullable List<CircuitBreakerConfigCustomizer> configCustomizer ) {
        return new CompositeCustomizer<>(configCustomizer);
    }

    @Singleton
    @Requires(beans = CircuitBreakerProperties.class)
    public CircuitBreakerRegistry circuitBreakerRegistry(
        CommonCircuitBreakerConfigurationProperties circuitBreakerConfigurationProperties,
        @CircuitBreakerQualifier EventConsumerRegistry<CircuitBreakerEvent> eventConsumerRegistry,
        @CircuitBreakerQualifier RegistryEventConsumer<CircuitBreaker> circuitBreakerRegistryEventConsumer,
        @CircuitBreakerQualifier CompositeCustomizer<CircuitBreakerConfigCustomizer> compositeCircuitBreakerCustomizer) {
        CircuitBreakerRegistry circuitBreakerRegistry = createCircuitBreakerRegistry(
            circuitBreakerConfigurationProperties, circuitBreakerRegistryEventConsumer,
            compositeCircuitBreakerCustomizer);
        registerEventConsumer(circuitBreakerConfigurationProperties, circuitBreakerRegistry, eventConsumerRegistry);
        initCircuitBreakerRegistry(circuitBreakerConfigurationProperties, circuitBreakerRegistry, compositeCircuitBreakerCustomizer);
        return circuitBreakerRegistry;
    }
}
```
