## Overview

The Resilience4j Spring 6 module provides integration with Spring Framework 6.x through annotation-driven AspectJ aspects, enabling declarative fault tolerance and performance monitoring across Spring application beans. By using Spring AOP around-advice interception alongside registry configuration beans and dynamic SpEL expression evaluation, the module decorates target method executions with resilience mechanisms including circuit breakers, rate limiters, bulkheads, retries, time limiters, and Micrometer timers.
Sources: [resilience4j-spring6/README.adoc:1-8](https://github.com/resilience4j/resilience4j/blob/main/resilience4j-spring6/README.adoc#L1-L8), [resilience4j-spring6/src/main/java/io/github/resilience4j/spring6/circuitbreaker/configure/CircuitBreakerAspect.java:43-67](https://github.com/resilience4j/resilience4j/blob/main/resilience4j-spring6/src/main/java/io/github/resilience4j/spring6/circuitbreaker/configure/CircuitBreakerAspect.java#L43-L67), [resilience4j-spring6/src/main/java/io/github/resilience4j/spring6/bulkhead/configure/BulkheadAspect.java:50-73](https://github.com/resilience4j/resilience4j/blob/main/resilience4j-spring6/src/main/java/io/github/resilience4j/spring6/bulkhead/configure/BulkheadAspect.java#L50-L73)

At runtime, target methods decorated with annotations such as `@CircuitBreaker`, `@Retry`, `@RateLimiter`, `@Bulkhead`, `@TimeLimiter`, or `@Timer` are intercepted by dedicated aspect components. These aspects extract annotation metadata, resolve configuration keys dynamically against method parameters using `SpelResolver`, and fetch or create resilience primitive instances from central registries (`CircuitBreakerRegistry`, `RetryRegistry`, `RateLimiterRegistry`, `BulkheadRegistry`, `TimeLimiterRegistry`, or `TimerRegistry`).
Sources: [resilience4j-spring6/src/main/java/io/github/resilience4j/spring6/circuitbreaker/configure/CircuitBreakerAspect.java:95-107](https://github.com/resilience4j/resilience4j/blob/main/resilience4j-spring6/src/main/java/io/github/resilience4j/spring6/circuitbreaker/configure/CircuitBreakerAspect.java#L95-L107), [resilience4j-spring6/src/main/java/io/github/resilience4j/spring6/retry/configure/RetryAspect.java:104-116](https://github.com/resilience4j/resilience4j/blob/main/resilience4j-spring6/src/main/java/io/github/resilience4j/spring6/retry/configure/RetryAspect.java#L104-L116)

The aspect architecture supports diverse method signature paradigms. Synchronous blocking calls are wrapped directly inside checked suppliers (`executeCheckedSupplier`), asynchronous methods returning `CompletionStage` or `CompletableFuture` are processed through dedicated completion stage handlers (`executeCompletionStage`), and reactive streams are adapted via specialized extension classes (`ReactorCircuitBreakerAspectExt`, `RxJava3CircuitBreakerAspectExt`, `RxJava2CircuitBreakerAspectExt`, etc.) that apply reactive operators onto `Publisher`, `ObservableSource`, `SingleSource`, `CompletableSource`, `MaybeSource`, and `Flowable` return types.
Sources: [resilience4j-spring6/src/main/java/io/github/resilience4j/spring6/circuitbreaker/configure/CircuitBreakerAspect.java:113-128](https://github.com/resilience4j/resilience4j/blob/main/resilience4j-spring6/src/main/java/io/github/resilience4j/spring6/circuitbreaker/configure/CircuitBreakerAspect.java#L113-L128), [resilience4j-spring6/src/main/java/io/github/resilience4j/spring6/circuitbreaker/configure/ReactorCircuitBreakerAspectExt.java:38-76](https://github.com/resilience4j/resilience4j/blob/main/resilience4j-spring6/src/main/java/io/github/resilience4j/spring6/circuitbreaker/configure/ReactorCircuitBreakerAspectExt.java#L38-L76), [resilience4j-spring6/src/main/java/io/github/resilience4j/spring6/circuitbreaker/configure/RxJava3CircuitBreakerAspectExt.java:21-78](https://github.com/resilience4j/resilience4j/blob/main/resilience4j-spring6/src/main/java/io/github/resilience4j/spring6/circuitbreaker/configure/RxJava3CircuitBreakerAspectExt.java#L21-L78)

When failures occur or limits are exceeded, execution seamlessly routes to reflection-based fallback methods via `FallbackExecutor` and `FallbackMethod`. These utilities perform exception hierarchy distance matching to select the closest matching fallback method parameter signature. Furthermore, internal schedulers supporting retries and time limiters can be configured to execute on Java virtual threads (Project Loom) via configuration property flags.
Sources: [resilience4j-spring6/src/main/java/io/github/resilience4j/spring6/fallback/FallbackMethod.java:47-75](https://github.com/resilience4j/resilience4j/blob/main/resilience4j-spring6/src/main/java/io/github/resilience4j/spring6/fallback/FallbackMethod.java#L47-L75), [resilience4j-spring6/README.adoc:8-30](https://github.com/resilience4j/resilience4j/blob/main/resilience4j-spring6/README.adoc#L8-L30)

## Aspect Infrastructure and Auto Configuration

The `resilience4j-spring6` module relies on Spring `@Configuration` classes to instantiate resilience registries, customizer beans, event consumer registries, and conditional aspect beans. Classes such as `CircuitBreakerConfiguration`, `RetryConfiguration`, and `RateLimiterConfiguration` import core dependencies (`FallbackConfiguration`, `SpelResolverConfiguration`) and wire the aspect pipeline into the Spring ApplicationContext.
Sources: [resilience4j-spring6/src/main/java/io/github/resilience4j/spring6/circuitbreaker/configure/CircuitBreakerConfiguration.java:51-53](https://github.com/resilience4j/resilience4j/blob/main/resilience4j-spring6/src/main/java/io/github/resilience4j/spring6/circuitbreaker/configure/CircuitBreakerConfiguration.java#L51-L53), [resilience4j-spring6/src/main/java/io/github/resilience4j/spring6/retry/configure/RetryConfiguration.java:54-56](https://github.com/resilience4j/resilience4j/blob/main/resilience4j-spring6/src/main/java/io/github/resilience4j/spring6/retry/configure/RetryConfiguration.java#L54-L56), [resilience4j-spring6/src/main/java/io/github/resilience4j/spring6/ratelimiter/configure/RateLimiterConfiguration.java:55-57](https://github.com/resilience4j/resilience4j/blob/main/resilience4j-spring6/src/main/java/io/github/resilience4j/spring6/ratelimiter/configure/RateLimiterConfiguration.java#L55-L57)

Aspect bean creation is guarded by `@Conditional(value = {AspectJOnClasspathCondition.class})`. The condition verifies whether `org.aspectj.lang.ProceedingJoinPoint` can be loaded by the application context classloader. If AspectJ is not present, aspect bean instantiation is bypassed while allowing core registries to function independently.
Sources: [resilience4j-spring6/src/main/java/io/github/resilience4j/spring6/utils/AspectJOnClasspathCondition.java:24-35](https://github.com/resilience4j/resilience4j/blob/main/resilience4j-spring6/src/main/java/io/github/resilience4j/spring6/utils/AspectJOnClasspathCondition.java#L24-L35), [resilience4j-spring6/src/main/java/io/github/resilience4j/spring6/circuitbreaker/configure/CircuitBreakerConfiguration.java:91-102](https://github.com/resilience4j/resilience4j/blob/main/resilience4j-spring6/src/main/java/io/github/resilience4j/spring6/circuitbreaker/configure/CircuitBreakerConfiguration.java#L91-L102)
